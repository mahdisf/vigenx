# ViGenX support routes

Use the route that preserves enough evidence for someone to act.

| Need | Route |
|---|---|
| Reproducible product defect | [Bug report](https://github.com/mahdisf/vigenx/issues/new?template=bug.yml) |
| Missing or contradictory documentation | [Documentation report](https://github.com/mahdisf/vigenx/issues/new?template=docs.yml) |
| New workflow, block, or engine behavior | [Feature proposal](https://github.com/mahdisf/vigenx/issues/new?template=feature.yml) |
| Setup question or design exploration | [GitHub Discussions](https://github.com/mahdisf/vigenx/discussions) |
| Security vulnerability | [Private security advisory](https://github.com/mahdisf/vigenx/security/advisories/new) |

Do not upload credentials, private media, copyrighted source footage, OAuth
tokens, cookies, model weights, or unredacted logs. A minimal synthetic fixture,
workflow JSON, exact command, and complete traceback are usually enough.
